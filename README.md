# 猫の手も借りたい

猫の両手で、ぜんぶお片付け。机の上の6個を片付けるまでの時間を競う、スマートフォン縦持ち向けの小さなブラウザゲームです。1ステージ・毎回同じ配置で、何度でもベストタイムに挑戦できます。

**ONE TAKE GAME #001** — Codexへの制作指示1回のみで制作しました。

## 遊び方

1. 「スタート」を押すと、3 → 2 → 1で開始します。
2. 1本指（PCではマウスの左ボタン）で画面をドラッグします。両手は指の約60px上を一緒に動きます。
3. 両手の間に物の中心を入れると、自動でつかみます。指を離しても保持します。再びドラッグして運べます。
4. 正しい箱の手前まで運ぶと自動で片付きます。間違った箱では箱が小さく震え、物を持ち続けます。
5. 6個を片付けた瞬間のタイムが記録されます。「もう一回」ですぐ再挑戦できます。

| 片付け先 | 物 |
| --- | --- |
| 左：ゴミ箱 | 空き缶、丸めた紙 |
| 中央：洗濯カゴ | 靴下、ハンドタオル |
| 右：おもちゃ箱 | ボール、ねずみのおもちゃ |

キーボードではTabでボタンを選び、EnterまたはSpaceで開始できます。プレイ中は矢印キーでも手を動かせます。音はありません。

## 起動

`index.html`をブラウザで開くだけで遊べます。npm、インストール、ビルド、サーバー処理は不要です。現在のChrome、Edge、Safari、Firefoxなど、CanvasとPointer Events対応のブラウザを使用してください。

ベストタイムは同じブラウザ・同じオリジンのlocalStorageに保存されます。ブラウザのデータを消すと記録も消えます。保存が制限された環境でもゲームは動き、そのページを開いている間はベストを保持します。ローカルファイルでの保存可否はブラウザによって異なります。

## GitHub Pagesで公開

1. このフォルダーの `index.html`、`style.css`、`game.js`、`README.md` をGitHubリポジトリのルートに置いてコミットします。
2. リポジトリの **Settings → Pages** を開きます。
3. **Build and deployment** の **Source** を **Deploy from a branch** にします。
4. ファイルを置いたブランチ（通常は `main`）と **/ (root)** を選び、**Save** します。
5. デプロイ完了後、Pagesに表示されるURLを開きます。

CSSとJavaScriptは相対パスで参照しているため、`https://ユーザー名.github.io/リポジトリ名/` のプロジェクトページでも動作します。GitHub Actions用のビルド設定は不要です。

## 使用技術と構成

- HTML / CSS / Vanilla JavaScript、Canvas 2D、Pointer Events
- 内部座標360×640。アスペクト比を維持し、画面とSafe Areaに収めて中央配置
- `performance.now()`による計測、単一の`requestAnimationFrame`ループ
- TITLE / COUNTDOWN / PLAYING / CLEAR / RESULTの5状態
- すべての図形・文字・ボタンをCanvasで描画。透明なHTMLボタンでキーボード操作と読み上げにも対応
- 外部画像、生成画像、SVG、絵文字、アイコンフォント、外部フォント、音声素材、外部ライブラリは一切不使用

`index.html`は画面とアクセシビリティ、`style.css`は画面へのフィット、`game.js`は入力・状態更新・判定・描画を担当します。

箱の判定範囲は手の可動範囲に合わせて箱の手前（y=185）まで延長しています。キャッチは約100ms、片付けは150msで描画し、最後の判定時にタイマーを止めた後、空の机を450ms表示して結果へ進みます。タブを離れた時間も計測に含まれます。

## 開発時の確認

実ブラウザでタイトル → カウントダウン → 全6個の片付け → 結果 → リトライを操作し、誤った箱での保持、320px幅の表示、コンソールエラーがないことを確認しています。スマートフォン実機での確認ではなく、ブラウザの縦画面サイズでの検証です。

任意の回帰テストは `node tests/game.test.cjs` で実行できます（Node.jsの標準機能のみ。ゲームの起動や公開には不要）。カウントダウン、6種類の判定、タイマー停止、タッチ入力・キャンセル・複数指の除外、保存失敗時の継続、ベストの更新・保持、複数回リトライ時のループやイベントの重複を検証します。`tests`フォルダーは公開時に省いても構いません。
